# Changelog

All notable changes to Weft are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project intends to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once it publishes releases.

Release notes are written in prose and describe the user-visible effect of each change, not just its label. A published release body must match the entry here.

## [Unreleased]

### Added

- Canvas workspace rework. Top-level frames and groups now carry screen-sized name labels on the canvas; clicking a label selects the frame, double-clicking enters it. Hover outlines use the same scope-aware hit testing as clicks and label the layer that would be selected, while selection, frame, hover, creation and transform labels stay readable at every zoom. The stage no longer imposes an arbitrary 800×600 minimum for non-empty pages: it follows the page's content bounds, with an 800×600 placeholder only for an empty page, so small designs do not float inside unexplained whitespace. Ctrl/Cmd+wheel zoom now stays anchored at the pointer, Fit resets scroll, and Space-drag or middle-button drag pans the canvas with grab/grabbing cursors. The page background is now a full-bleed workspace backdrop rather than a second bordered sheet behind the main frame (ADR 0029); empty pages keep a dashed placeholder. Persistent frame labels and hover outlines are editor chrome only and never enter the design file or exports. The canvas remains a finite page surface; rulers, guides, snapping, zoom-to-selection, minimap, inertia, true frame isolation and a hand tool remain follow-ups. This adds ADR 0028, a canvas guide, and updates to the editor, architecture, history and README docs; the 250-test gate is unchanged because this is UI-only.
- Live session panel, frontend attach and capture. The top bar now always exposes the actual host as a **Live** (or **Preview**) button. Its panel lists the running editor URL, API base, health check, WebSocket endpoint, design path, workspace file and project root read from the bridge's new runtime `bridge` object, with copy actions. It also contains the project-server controls. A new **Frontend target** field accepts a complete loopback URL such as `http://127.0.0.1:3000/`; the bridge rejects non-loopback hosts, credentials, fragments and non-HTTP schemes, probes without following redirects or consuming the body, reports reachable/error state, and broadcasts every change. The URL is saved in browser `localStorage`, reattached after reload, never written to the project, and can be opened or shown in a sandboxed cross-origin iframe. **Capture page** re-probes the attached target, captures the active page through the existing sanitizer and verifier using the selected or first root frame viewport, optional CSS selector and page id, reloads the bridge from disk, auto-selects the new snapshot and shows warnings. The exact attached loopback origin becomes the explicit capture allowlist for that action; the CLI still requires `extract.origins`. New authenticated routes are `GET`/`POST`/`DELETE /api/frontend` and `POST /api/frontend/capture`, with Origin checks, bounded inputs, one capture at a time and no browser-supplied commands. Capture remains a static snapshot and is not part of command undo. This adds ADR 0027, a live-session guide, project-server/frontend integration in the panel, and new bridge and extraction tests.
- Founding repository: the product definition, the working architecture, and two decision records — the name **Weft**, and the choice of plain-text, git-friendly design files as the canonical artifact that any coding agent can read and write.
- `@weft/core`, the shared document model: a design is a manifest plus one page per file, with nodes in a flat id-addressed map, stable prefixed ULIDs, real text content, token references, captured-page snapshots stored beside the page, and a deterministic JSON writer so identical designs produce identical bytes and reviewable git diffs. The package also ships pure insert, move, reorder, duplicate, remove and update operations, and a dependency-free validator that reports typed, pathed issues for broken references, cycles, unreachable nodes, unresolved tokens and assets, unsafe paths and malformed snapshot metadata.
- A small starter design in `examples/starter.weft/`, readable end to end, exercised by 94 unit tests together with the schema, serialization, validation and operation suites.
- `@weft/design-io`, the Node filesystem layer for design directories. It reads a manifest and the pages it lists, reports schema and file problems together with file-prefixed paths, resolves design-relative paths without allowing escapes, writes manifest and pages atomically with deterministic serialization, formats files into canonical form, initializes new designs without overwriting a non-empty directory unless forced, and checks that referenced asset and snapshot files exist. It also produces the compact summary used by agents.
- The `weft` CLI, the first executable client of the document contract: `weft init`, `weft validate`, `weft fmt` and `weft inspect`, each with human-readable and `--json` output and stable exit codes (`0` success, `1` validation or I/O failure, `2` usage error). `fmt --check` supports CI and pre-commit use, and `validate` distinguishes schema issues from missing files.
- Asset paths are no longer restricted to a fixed list of image/video extensions, so fonts and other design assets can live beside the design without being rejected by the schema.
- The command protocol: serializable page mutations for inserting, updating, moving, removing, duplicating and replacing nodes, plus atomic subtree insertion. Every applied command returns an inverse computed from the document before the change, so a command followed by its inverse restores a byte-identical page. Commands carry a `cm_` id, page id, ISO timestamp and optional human/agent/system actor in an envelope, and untrusted command JSON is parsed with stable error codes before anything is applied.
- Three new CLI commands built on the protocol. `weft apply` reads `{pageId, command, actor?}` from a file or stdin, validates the result, writes atomically, and returns the command id, created node ids, inverse and written files; `--dry-run` returns the same without writing. `weft get` prints a page document or a node with its page context as JSON. `weft id` generates prefixed ULIDs for designs, pages, nodes, assets and commands, so an agent can allocate ids before inserting a node.

- `@weft/contract`, a published structural contract: a JSON Schema draft 2020-12 covering manifests, pages, every node type, paints, styles, layouts, tokens, assets, snapshots, patches, commands, command requests and envelopes, with a versioned `$id` and shared `$defs`. It is hand-maintained and checked against the TypeScript types and validators by a conformance suite.
- A conformance fixture suite that distinguishes structural failures from semantic ones. Valid fixtures must pass both the schema and the core; schema-invalid fixtures must fail both; semantic-invalid fixtures must pass the schema while still failing the core for dangling children, unreachable nodes, multiple parents, unresolved tokens or unsafe paths. The suite also validates the starter design and a page containing every v1 node type, so the schema cannot silently drift.
- `@weft/session`, a Yjs-backed live page session. Node fields are Y.Map registers, parent and fractional order keys live in a separate placement map, and children arrays are derived during materialization, so no `Y.Array` move can duplicate or drop a node. Commands use the same core implementation as the CLI and return their inverse. Two clients that join the same Yjs structure converge after exchanging updates.
- Whole-page file-write ingestion with a three-way merge between the last materialized baseline, the live page and the incoming file. Non-conflicting changes apply; conflicting fields keep the live value and are reported with paths; a file that removes a modified subtree keeps the live subtree and reports a conflict instead of deleting it. The session never writes CRDT metadata into the design file.
- `@weft/render`, a read-only DOM renderer for pages: absolute frame geometry, CSS flex layout, real text, token-resolved colors and font families, solid/gradient/image paints, strokes, radius, shadows, blur, page backgrounds, computed page bounds, asset URL resolution, and sandboxed snapshot iframes when a payload is supplied.
- `apps/web`, the browser editor: a Vite 8 + React 19 app that starts as a static read-only preview loaded through a `virtual:weft-design` plugin and, when served by `weft dev`, becomes a live editor. It shows page tabs, node count, zoom, file changes, conflicts and connection status, and renders frames, flex layout, text, tokens, paints and page bounds as real DOM. `WEFT_DESIGN` points the static preview at another design. Images and snapshots render as placeholders until the asset pipeline supplies them.
- `@weft/bridge` and `weft dev <design.weft>`, the live local loop. The bridge serves the built app, watches the design directory, keeps one Yjs `PageSession` per page, ingests whole-page writes, and streams Yjs updates over `/api/live`. `GET /api/design` bootstraps the manifest and per-page updates. Invalid writes broadcast an error and keep the last good state. The app detects a JSON `/api/design` response, builds sessions, connects to the WebSocket, applies updates, and shows live/connecting/offline status. Editing a design with the CLI updates the open browser without rebuilding.
- Browser editing. Click a layer on the canvas to select it, inspect and edit name, geometry, opacity, fill and text content, delete it, and undo or redo with buttons or Cmd/Ctrl+Z. The selection box follows the DOM layout and live updates. The inspector is intentionally a small property sheet: no drag/resize, layer tree, multi-select, components or page-level commands yet.
- A bidirectional command channel over the live bridge. The app sends `command` messages with a `cm_` command id and an actor; the bridge validates, applies to the Yjs session, writes the changed page atomically with `writePageFile`, marks the session baseline, returns the inverse with `commandResult`, and broadcasts attribution. A failed disk write applies the inverse and rolls the live session back. The bridge is now a canonical writer, not only a watcher.
- Client-side undo/redo stacks backed by command inverses: a successful command pushes its inverse, undo pushes the undo result's inverse onto redo, redo pushes back onto undo. History clears on reconnect, and external CLI/agent file edits remain outside the browser history.
- `writePageFile` in `@weft/design-io`: single-page atomic writes with page validation, used by the bridge and tested independently.
- A light/dark UI theme that defaults to the system preference, switches from the toolbar with a sun/moon control, and persists in `localStorage`. The top bar, canvas, inspector, inputs, buttons, status badges, selection chrome and hints are theme-aware; design content keeps its own colors. The inspector is grouped into Layer, Layout, Appearance and Content sections, with a compact shortcut hint and a cleaner toolbar.
- The workspace picker: `weft workspace dev` starts one live bridge over the registered workspace, and the browser shows a project/design selector in the top bar. Switching designs validates the target against the registry, rebuilds the page sessions, broadcasts a fresh init to every connected tab, and rejects unregistered paths. The editor and inspector continue on the new design without restarting the process.
- Direct move and resize. The selected layer can be dragged on the canvas and resized with eight handles; the selection box hides during the gesture and a preview outline shows the incoming bounds. Movement adds the page-space delta to local `x`/`y`, resize clamps to at least 1 px and adjusts west/north edges so the opposite edge stays fixed, and a move/resize round-trips through one `node.update` command with an inverse. Transient DOM styles provide live feedback but are restored on release/cancel; nothing is written to the page or Yjs until the command. Handles live inside the selection bounds so the clipped stage does not swallow their hit areas, and are scaled to stay roughly 8 screen pixels. Locked nodes do not start a gesture. Single selection only; flex children may ignore a movement command, and there is no snapping, aspect lock, rotation handle or multi-select yet.
- Multi-selection and batch commands. Shift/Cmd/Ctrl-click on the canvas or in the layer tree adds or removes layers; the inspector switches to a multi-layer summary. Dragging any selected layer moves the selection roots together as one `batch` of `node.update` commands, and Delete removes the roots as one `batch` of `node.remove` commands, so a gesture produces one undo entry and one page write. Selection boxes use dashed individual outlines, resize handles remain single-layer only, and parent+child selections are filtered to roots to avoid double movement. The `batch` command is capped at 200 non-nested subcommands, composes inverses in reverse order, and is shared by the bridge, CLI and MCP. Browser text selection inside the stage is disabled so modifier clicks do not highlight the rendered design text. Multi-resize, marquee selection, alignment tools and range selection remain follow-ups.
- Batch alignment and keyboard nudge. The multi-layer inspector gains six alignment buttons (left/center/right/top/middle/bottom) that align selection roots to the selected group's bounds. Arrow keys nudge the selection by 1 px, Shift+Arrow by 10 px, both committed as one `batch` of `node.update` commands with one inverse. Parent+child selections align/nudge roots only. Flex children get an explicit warning because the parent layout may override x/y; width/height still participate in flex sizing. No distribute, align-to-page or match-size tools yet.
- Static HTML export and handoff. `weft export <design> --out <dir>` server-renders the selected pages with the canonical DOM renderer and writes standalone HTML, an index, `tokens.json` and `weft.export.json` with design/page metadata and dimensions. Snapshot payloads remain in sandboxed iframes and no scripts are added; image nodes remain placeholders until the asset pipeline exists. Single-page export, `--force` for non-empty output directories, and JSON output are supported. The output directory is never cleaned of unrelated files; generated paths are derived from page names. `@weft/export` contains the reusable server-side renderer, and ADR 0022 records the handoff boundary.
- Figma-inspired selection scopes and marquee. At page scope a click selects the top-level frame; double-click enters the nearest frame/group and selects the clicked layer. Inside a scope, clicks select the direct child, the scope frame background selects the frame, and Escape moves one level up. A breadcrumb shows Page / Frame / … and changes scope on click. Dragging empty page background marquee-selects top-level layers; dragging the scope frame background selects its direct children. Matches are measured from rendered DOM boxes, Shift adds them, and the marquee is editor chrome only. Scope is an interaction lens, not visibility isolation; surrounding layers stay visible. Layer-tree selection sets the matching parent scope, and select-all respects the scope. Duplicate IDs are still not auto-selected.
- Canvas navigation and layer controls. The toolbar now has zoom out, current percentage (click for actual size), zoom in and Fit; Cmd/Ctrl+0/=/− and Ctrl/Cmd+wheel zoom, and the canvas scrolls when zoomed beyond the viewport with a non-shrinking stage and safe centering. Layer rows gain visibility and lock actions backed by ordinary `node.update` commands; locked layers are excluded from move/resize/delete/duplicate/nudge/alignment, and hidden layers disappear from the canvas but remain in the tree. Cmd/Ctrl+A selects all layers, Cmd/Ctrl+D duplicates unlocked selection roots as one batch, and Escape clears selection. Duplicates are not auto-selected yet.
- Live and static image assets. Manifest image and paint assets now render in the editor instead of placeholders. The bridge serves `GET/HEAD /api/asset/<id>` only for manifest assets, after cookie authorization, with `readAssetFile` path/symlink/size checks, a media/font MIME allowlist, `no-store`, same-origin resource policy and a script-free CSP with sandbox. The app cache-busts URLs with the bridge revision. The static Vite preview embeds manifest assets as data URLs. Unknown assets keep the renderer placeholder. Asset upload, thumbnails, content hashing, font-family mapping and responsive variants remain follow-ups.
- Static export now copies local manifest assets. Image nodes and image paints render real files under `assets/<asset-id><ext>` instead of placeholders; page HTML rewrites URLs as `../assets/...` and `weft.export.json` lists the exported asset ids, names, MIME types and files. Assets are read only from the design directory through the safe-path resolver and written atomically under the output's `assets/`. Font assets are copied but no `@font-face` mapping, content hashing, thumbnails, deduplication or editor asset serving is added yet.
- Combined multi-selection resize. When every selected root uses absolute layout and is unlocked, the dashed multi-selection group box gains eight resize handles. Dragging scales each root's absolute position and size from the group bounds, converts back to parent-local geometry and commits one `batch` of `node.update` commands for one undo step. The transient DOM preview sets width/height/translate and restores on release/cancel. Flex-bound selections hide the group handles and show the existing flex warning, because a flex parent may override x/y and width/height. No aspect-ratio lock, rotation-aware bounds, distribute or flex-aware resize yet.
- Empty-page guidance. A page with no layers now shows an in-artboard **Empty page** hint pointing to the creation tools, instead of leaving a blank colored rectangle that can look like unexplained whitespace. The hint is editor chrome only and never enters the design file.
- Page organization. `page.rename` and `page.move` document commands let pages be renamed and reordered with computed inverses. Renames update both the page document and manifest reference while keeping the page file path stable; moves reorder both arrays and write only the manifest. The shared file transaction writes the renamed page then manifest, restoring the old page if the manifest write fails. The browser adds inline page-tab rename (double-click, Enter/blur to commit, Escape to cancel), a Rename page action, and drag-and-drop tab reordering with a drop target. `weft page rename/move` expose the same operations, and MCP accepts them through `weft_page_command`. Rename/move join the mixed page/node undo history. Page duplicate, cross-design drag and multi-page drag are still follow-ups.
- The agent MCP surface. `@weft/mcp` and `weft mcp` expose the document contract over stdio: list allowlisted designs, read summaries/pages/nodes, validate, apply `PageCommand`s, apply `page.create`/`page.remove` document commands, and return a structured context packet. Writes reuse the same validation, atomic file transactions and inverses as the CLI/browser, and include a command id, actor and inverse. The server is configured with a workspace registry or a single design directory, canonicalizes every design path and rejects anything outside that startup allowlist. `--read-only` disables both write tools. The fixed `mcp` agent actor is attributed on every write; per-call spoofing and a durable audit log are not included. There is no screenshot tool yet, no MCP resources/prompts, and no HTTP listener; the workspace allowlist is loaded at startup. The context packet carries an explicit warning that captured page text is untrusted data.
- Page-level document commands and page creation/deletion in the browser. The new `DocumentCommand` contract (`page.create`, `page.remove`) changes the manifest and page files, returns a computed inverse, and validates the resulting design. The bridge accepts document commands over the live WebSocket, writes the page file and manifest in a safe order, removes the page file on deletion, rebuilds sessions and broadcasts a design-command init. The editor's left panel now has **New page** and **Delete page** actions; new pages become active, deletion confirms and refuses the last page, and page create/delete share the node history's undo/redo stacks. Deleted page content is carried in the inverse so undo can restore it. Page ids, safe file paths, manifest collisions and the last-page invariant are enforced in core. Browser page creation is no longer a limitation; `weft page create/remove/apply` exposes the same commands to agents and scripts. Page rename/reorder and dedicated document-command fixtures remain follow-ups.
- Browser creation tools and a layer tree. The editor now has a left panel with Select, Frame, Text, Rectangle and Ellipse tools (`V`, `F`, `T`, `R`, `O`), drag-or-click creation with sensible default sizes and styles, and automatic parent placement when a container is selected. Every creation uses the same `node.insert` command as the CLI and agents, so it is validated, written to the canonical page file, attributed and undoable through the existing inverse stack. The new node is selected after materialization. The panel also contains a nested, collapsible layer tree with type icons, canvas-synchronized selection, keyboard navigation and auto-expansion to the selected ancestor. The tools are disabled in the static preview. Browser page creation/deletion, drag/resize, multi-select and layer reordering remain follow-ups. The layer tree reduces canvas width, so the fit scale adjusts; narrow viewports hide the panel.
- Snapshot extraction. `weft extract <design> <url> --project <root>` captures one allowlisted loopback page with headless Chromium, collects the selected subtree and computed styles, inlines same-origin images as data URLs, and writes sanitized HTML/CSS under `snapshots/` beside the page. It inserts a normal snapshot node with source URL, selector, viewport and capture time; the page is written last, and a failed page write removes the new payload. Capture only starts when the exact origin is in the project's `weft.project.json` `extract.origins`; HTTP and WebSocket traffic during capture is restricted to those origins, service workers/dialogs/popups are blocked, and a fresh browser context is used. Executable markup, forms, frames, event handlers and external URLs are removed by the browser pass; a dependency-free Node verifier then fails closed if any executable construct or non-data URL survives. The editor renders the result in a `sandbox=""` iframe under a CSP that allows only inline styles and data images, so captured scripts never run. Snapshot payloads load in the static Vite preview and in the live bridge, including a fresh `init` when an extraction adds a node and its files. Captured text remains untrusted data and can carry prompt-injection attempts; that limit is documented rather than hidden.
- Declared project dev servers. A registered project can put a `weft.project.json` at its root with a loopback `devServer.url` and an optional argv `command`; without a command, Weft attaches to an already-running server instead of owning it. The bridge starts and stops one server per project through authenticated `/api/dev` routes, polls the URL until it answers below 500, captures bounded stdout/stderr, rejects symlinked configs and cwd escapes, and reports early exits or readiness timeouts with the relevant output. The browser's project-server section in the Live panel shows the URL, status, pid and recent logs and offers Start/Attach and Stop. Managed children run without a shell in a process group; stop sends `SIGTERM`, then `SIGKILL` to the group so package-manager and compiler children do not orphan, and closing the bridge stops every managed server. Commands are never accepted from the browser; the declaration is the approval boundary, and the command still runs with the user's permissions rather than in a sandbox.
- The first workspace slice: `@weft/workspace` and `weft workspace init/add/list/remove`. A registry file (`$WEFT_WORKSPACE` or `~/.weft/workspace.json`) holds explicitly registered project roots with canonical real paths, unique names and timestamps. Discovery finds design directories containing `weft.json` inside a registered root while skipping `node_modules`, `.git`, build outputs and symlinked directories. The registry writes atomically with owner-only permissions and reports missing roots instead of silently dropping them. The workspace picker and declared dev-server manager now consume this allowlist; the bridge can still be run against one design directory explicitly with `weft dev`.
- Local bridge hardening: loopback-only bind hosts, a random per-run `HttpOnly`/`SameSite=Strict` session cookie, required authorization on `/api/design`, `/api/live` and `/api/dev`, Host and Origin checks that block DNS rebinding and cross-origin browser requests, constant-time token comparison, a 1 MiB WebSocket payload cap, and restrictive security headers. The browser app receives the cookie automatically; restarting the bridge rotates it and requires open tabs to reload. This is single-user local hardening, not team authentication.
- A repository security baseline: a CI workflow that builds, typechecks, tests, validates and canonicalizes the starter design, and audits dependencies; CodeQL, dependency review, Dependabot, CODEOWNERS and a PR template; `SECURITY.md`, a threat model and a local-workspace design; and scripts for branch protection and repository security settings. `main` now requires pull requests, the `verify`, `analyze` and `dependency-review` checks, with linear history, conversation resolution and no force pushes or deletions.
- The CLI suite is now 28 tests, core 117, design I/O 25, contract 8, the workspace registry 9, the dev-server manager 12, the bridge 16, extraction 8 (plus one opt-in browser test), MCP 4 and export 4; the repository has 250 tests across the document model, design I/O, CLI, contract, session, renderer, bridge, workspace registry, dev-server supervision, extraction, editor command loop, frontend attach/capture and bridge security boundary.
