# Project history

This is the narrative record of **what Weft was built with, why, what changed, and why**. `CHANGELOG.md` is the user-facing record of what shipped; `docs/decisions/` holds the reasoning in detail; this file is the map between them.

**How to update:** add a row to the timeline whenever the stack, architecture, contract, or product strategy changes, or when a release marks an era boundary. Link the ADR that explains it. Never rewrite history — correct it with a dated note instead.

Foundation** | Oct 2026 – current | Read-only DOM preview (`apps/web`, ADR 0008) | Plain-text `.weft/` directory (ADR 0002), v1 schema implemented in `@weft/core` (ADR 0003), headless CLI over `@weft/design-io` (ADR 0004), command protocol with inverses (ADR 0005), published JSON Schema (ADR 0006), Yjs live session with file-write merge (ADR 0007) | Yjs session implemented | Files + CLI commands + contract + live session + read-only preview now; editing + bridge planned | Establish the product definition, the decisions everything depends on, and a tested document model: an agent-native, browser-native canvas with the design file as the durable artifact. | *Read-only preview only. Editing, the local bridge, the agent contract and extraction remain. ## Timeline

| Date | Release / event | What changed | Why | Record |
| --- | --- | --- | --- | --- |
| 2026-10-25 | Project named **Weft** | Chose a one-word name from the weaving metaphor: designer and agent are the warp and weft of one design. Rejected Kern, Gesso, Tessera, Maquette, Vellum, and taken names such as Loom and Lattice. | The repository, CLI, package scope, and file format all need a stable name before code exists. | ADR 0001 |
| 2026-10-25 | Design files are plain-text documents | Chose a `.weft/` directory of deterministic JSON and assets as the canonical artifact, with Yjs as the live editing layer and the bridge as the only file writer. | Agents must be able to read, diff, and write designs without a proprietary API; git must remain the history; the file must outlive the editor. | ADR 0002 |
| 2026-10-25 | Product definition and draft architecture recorded | Wrote the personas, jobs, principles, non-goals, MVP exit criteria, system shape, risks, and the list of decisions still to make. | Give the first implementation a criterion-driven target instead of a calendar or a vibe. | ADR 0001, ADR 0002 |
| 2026-10-25 | Repository scaffolded | Created the monorepo skeleton, MIT license, decision-record system, and documentation. | Make the project contributable before the first line of product code. | — |
| 2026-10-25 | Document schema v1 implemented | Shipped `@weft/core`: flat node maps with stable ULIDs, page/manifest types, deterministic serialization, hand-written validation, and pure insert/move/remove/duplicate/update operations. The starter design in `examples/starter.weft/` is validated in the test suite. | A schema that agents can address and git can diff is the foundation for every other component; prove it in unit tests before building an editor on it. | ADR 0003 |
| 2026-10-25 | Headless Weft | Shipped `@weft/design-io` and the `weft` CLI: `init`, `validate`, `fmt`, `inspect`, human and `--json` output, stable exit codes, safe paths, atomic writes, canonical formatting, asset/snapshot existence checks, and a compact design summary. | Agents work in a terminal. The smallest real client proves the contract, gives CI and agents a safety net, and keeps the editor from becoming the first place the format is tested. | ADR 0004 |
| 2026-10-25 | Command protocol and CLI editing | Added serializable `PageCommand`s with computed inverses, `cm_` command envelopes, attribution metadata, `weft apply` (with `--dry-run`), `weft get`, and `weft id`. Every command/inverse pair is tested to restore a byte-identical page. | Undo, dry-runs, attribution and agent edits need one mutation vocabulary shared by the CLI, the future editor and the bridge. Whole-file writes alone cannot carry intent or an undo path. | ADR 0005 |
| 2026-10-25 | Published structural contract | Added `@weft/contract`: a JSON Schema draft 2020-12 for manifests, pages, commands, command requests and envelopes, plus a conformance fixture suite that runs Ajv and the core validator over the same valid, schema-invalid and semantic-invalid cases. | Non-TypeScript clients and agents should not have to read our implementation to know a valid shape, and the schema, types and validators need an executable guard against drift. | ADR 0006 |
| 2026-10-25 | Live page session and file-write reconciliation | Added `@weft/session`: a Yjs-backed page with node Y.Maps, a separate parent/fractional-order placement map, derived children arrays, command application with inverses, two-client convergence, and conservative three-way ingestion of whole-page file writes with explicit conflicts. | Human live edits and agent file writes must coexist without silent loss. The session settles the concurrency semantics before the editor and bridge are built on them. | ADR 0007 |
| 2026-10-25 | Read-only browser preview | Added `@weft/render` and `apps/web`: a Vite 8 + React 19 app that embeds a design through `virtual:weft-design`, renders frames, flex layout, real text, tokens, paints, shadows and page bounds as DOM, and fits the page to the viewport. No editing or bridge yet. | The schema and session needed a visible surface, and the DOM-first renderer needed to be proven against the real starter design before editing, selection and panels add complexity. | ADR 0008 |
