# Project history

This is the narrative record of **what Weft was built with, why, what changed, and why**. `CHANGELOG.md` is the user-facing record of what shipped; `docs/decisions/` holds the reasoning in detail; this file is the map between them.

**How to update:** add a row to the timeline whenever the stack, architecture, contract, or product strategy changes, or when a release marks an era boundary. Link the ADR that explains it. Never rewrite history — correct it with a dated note instead.

## Eras

| Era | Period | Editor | Document | Realtime | Agent surface | Why it was chosen | What turned out to be wrong / why we moved on |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **0. Foundation** | Oct 2026 – current | Live DOM editor with selection, inspector and undo (`apps/web`, ADR 0008/0010) | Plain-text `.weft/` directory (ADR 0002), v1 schema implemented in `@weft/core` (ADR 0003), headless CLI over `@weft/design-io` (ADR 0004), command protocol with inverses (ADR 0005), published JSON Schema (ADR 0006), Yjs live session with file-write merge (ADR 0007) | Yjs session + live bridge implemented | Files + CLI commands + contract + live session + live browser editing + creation tools/layer tree + page commands + workspace picker + declared dev servers + snapshot extraction + MCP agent surface now | Establish the product definition, the decisions everything depends on, and a tested document model: an agent-native, browser-native canvas with the design file as the durable artifact. | *Editing now covers selection, a small inspector, node and page creation, page deletion, direct move/resize, multi-selection with batch move/delete/resize, alignment/nudge, page rename/reorder, mixed undo and a read-only layer tree, but still has no multi-resize or layer reordering. The MCP agent surface is available; export, deeper permissions and page rename remain. Capture is a CLI path today, not a bridge button, and captured pages are readable snapshots rather than pixel-identical clones. The loop is proven by tests and manual browser editing: selection → command → page write → Yjs update → undo.* |

## Timeline

| Date | Release / event | What changed | Why | Record |
| --- | --- | --- | --- | --- |
| 2026-10-25 | Project named **Weft** | Chose a one-word name from the weaving metaphor: designer and agent are the warp and weft of one design. Rejected Kern, Gesso, Tessera, Maquette, Vellum, and taken names such as Loom and Lattice. | The repository, CLI, package scope, and file format all need a stable name before code exists. | ADR 0001 |
| 2026-10-25 | Design files are plain-text documents | Chose a `.weft/` directory of deterministic JSON and assets as the canonical artifact, with Yjs as the live editing layer and the bridge as the only file writer. | Agents must be able to read, diff, and write designs without a proprietary API; git must remain the history; the file must outlive the editor. | ADR 0002 |
| 2026-10-25 | Product definition and draft architecture recorded | Wrote the personas, jobs, principles, non-goals, MVP exit criteria, system shape, risks, and the list of decisions still to make. | Give the first implementation a criterion-driven target instead of a calendar or a vibe. | ADR 0001, ADR 0002 |
| 2026-10-25 | Repository scaffolded | Created the monorepo skeleton, MIT license, decision-record system, and documentation. | Make the project contributable before the first line of product code. | — |
| 2026-10-25 | Document schema v1 implemented | Shipped `@weft/core`: flat node maps with stable ULIDs, page/manifest types, deterministic serialization, hand-written validation, and pure insert/move/remove/duplicate/update operations. The starter design in `examples/starter.weft/` is validated in the test suite. | A schema that agents can address and git can diff is the foundation for every other component; prove it in unit tests before building an editor on it. | ADR 0003 |
| 2026-10-25 | Headless Weft | Shipped `@weft/design-io` and the `weft` CLI: `init`, `validate`, `fmt`, `inspect`, human and `--json` output, stable exit codes, safe paths, atomic writes, canonical formatting, asset/snapshot existence checks, and a compact design summary. | Agents work in a terminal. The smallest real client proves the contract, gives CI and agents a safety net, and keeps the editor from becoming the first place the format is tested. | ADR 0004 |
| 2026-10-25 | Command protocol and CLI editing | Added serializable `PageCommand`s with computed inverses, `cm_` command envelopes, attribution metadata, `weft apply` (with `--dry-run`), `weft get`, and `weft id`. Every command/inverse pair is tested to restore a byte-identical page. | Undo, dry-runs, attribution and agent edits need one mutation vocabulary shared by the CLI, the future editor and the bridge. Whole-file writes alone cannot carry intent or an undo path. | ADR 0005 |
| 2026-10-25 | Published structural contract | Added `@weft/contract`: a JSON Schema draft 2020-12 for manifests, pages, commands, command requests and envelopes, plus a conformance fixture suite that runs Ajv and the core validator over the same valid, schema-invalid and semantic-invalid cases. | Non-TypeScript clients and agents should not have to read our implementation to know a valid shape, and the schema, types and validators need an executable guard against drift. | ADR 0006 |
| 2026-10-25 | Live page session and file-write reconciliation | Added `@weft/session`: a Yjs-backed page with node Y.Maps, a separate parent/fractional-order placement map, derived children arrays, command application with inverses, two-client convergence, and conservative three-way ingestion of whole-page file writes with explicit conflicts. | Human live edits and agent file writes must coexist without silent loss. The session settles the concurrency semantics before the editor and bridge are built on them. | ADR 0007 |
| 2026-10-25 | Read-only browser preview | Added `@weft/render` and `apps/web`: a Vite 8 + React 19 app that embeds a design through `virtual:weft-design`, renders frames, flex layout, real text, tokens, paints, shadows and page bounds as DOM, and fits the page to the viewport. No editing or bridge yet. | The schema and session needed a visible surface, and the DOM-first renderer needed to be proven against the real starter design before editing, selection and panels add complexity. | ADR 0008 |
| 2026-10-25 | Live local bridge | Added `@weft/bridge` and `weft dev <design.weft>`: a local server that watches the design directory, keeps a Yjs page session, serves the built app and `/api/design`, and streams Yjs updates over `/api/live`. The app detects the bridge and switches from static to live. Editing a file with the CLI now updates the open browser without a rebuild. | The product loop is file change → live browser, and the session engine needed a real transport. The bridge initially shipped read-only; commands and writes followed in the editor interaction slice. | ADR 0009 |
| 2026-10-25 | Combined multi-selection resize | Added a dashed group box and eight resize handles for absolute-layout selections. Resizing scales each root's absolute position/size, converts to local geometry and commits one batch; flex-bound groups hide handles and keep the flex warning. | After multi-move/align, group scaling was the remaining basic transform. Restricting it to absolute roots avoids silent flex no-ops while reusing the batch/inverse path. | ADR 0021 |
| 2026-10-25 | Batch alignment and keyboard nudge | Added six group alignment actions and arrow-key nudging (Shift for 10 px), both as one batch of node updates. Flex children show an explicit warning because parent layout may ignore x/y. | Multi-select made group movement possible but precision still required per-layer edits. Alignment/nudge reuse the batch command and inverse path without adding a layout engine. | ADR 0020 |
| 2026-10-25 | Multi-selection and batch commands | Added modifier selection on canvas/layer tree, multi-selection outlines and inspector, batch move/delete through a new non-nested `batch` page command with reverse-order inverses, selection-root filtering, and disabled native text selection on the stage. | Single-layer gestures left repetitive work and multiple undo entries. A batch command keeps one gesture to one page write and one inverse without inventing a browser-only bulk path. | ADR 0019 |
| 2026-10-25 | Page organization | Added `page.rename`/`page.move` document commands with inverses, shared page-file/manifest transactions, inline page-tab rename, drag reorder, page Rename/Delete actions and CLI rename/move. | Creation and deletion were not enough to shape navigation; page organization needed the same document command and undo model as page creation. | ADR 0018 |
| 2026-10-25 | Direct layout manipulation | Added drag-to-move and eight resize handles for the selected layer. Gestures preview through transient DOM styles, commit one `node.update` on release, preserve parent-relative coordinates and use the normal inverse undo path. | Creation tools still left exact layout to the inspector. Direct manipulation is the expected canvas interaction, and one command per gesture keeps the file/undo model atomic. | ADR 0017 |
| 2026-10-25 | Agent MCP surface | Added `@weft/mcp` and `weft mcp` over stdio: allowlisted design reads, summaries/page/node JSON, validation, page and page-document commands with dry-run and inverses, context packets and `--read-only`. Every write is attributed to the fixed MCP actor. | Harnesses already work through files and the CLI, but MCP gives pi/opencode/Claude Code/Codex one documented tool surface. The startup allowlist and stdio-only boundary keep it from becoming a network or arbitrary-filesystem server. | ADR 0016 |
| 2026-10-25 | Page CLI surface | Added `weft page create/remove/apply` and a shared `writeDocumentCommand` file transaction, so agents and scripts can use the same page commands as the browser and bridge. | Page creation was browser/bridge-only; the agent-native contract needs a file/CLI surface that returns the same inverses. | ADR 0015 |
| 2026-10-25 | Page-level document commands | Added `DocumentCommand` (`page.create`, `page.remove`) with computed inverses, bridge `designCommand` transport, manifest/page-file transactions, page create/delete UI actions and mixed page/node undo. Page deletion removes the file after the manifest is written; the inverse carries the page content. | Node tools alone could not start a new page. Page mutations change the manifest and page set, so they needed a document-level contract rather than a page-scoped command or a browser-only file write. | ADR 0015 |
| 2026-10-25 | Creation tools and layer tree | Added a left tool panel for frames, text, rectangles and ellipses, drag-or-click creation through the ordinary `node.insert` command, parent-aware placement inside a selected frame, a nested layer tree with selection and auto-expansion, and keyboard tool shortcuts. | The editor could only modify a pre-existing starter; creation and a structural layer view are the minimum for starting a design in the browser without introducing a parallel mutation path. Page creation remains a document-level follow-up. | ADR 0014 |
| 2026-10-25 | Snapshot extraction | Added `@weft/extract` and `weft extract`: exact loopback-origin allowlisting, headless Chromium capture, computed-style serialization, data-URL asset inlining, a browser sanitizer plus a fail-closed verifier, source metadata and snapshot files beside the page. The renderer and bridge load payloads into sandboxed CSP iframes; the static preview and live init carry them too. | Extraction turns the running product into readable design evidence without shipping executable HTML. The allowlist and sanitizer boundary must exist before agents or a UI can ask for a capture. | ADR 0013 |
| 2026-10-25 | Declared project dev servers | Added `@weft/dev-server` and `weft.project.json` support: an argv command or attach-only URL, loopback validation, cwd realpath containment, readiness polling, bounded logs, per-project start/stop over authenticated bridge routes, a browser Project server panel, and process-group shutdown on stop or bridge close. | Extraction needs the running product, and a browser must never be able to supply a command. The declaration is the approval boundary; the manager keeps the execution surface narrow while making first-run and readiness observable. | ADR 0012 |
| 2026-10-25 | Workspace picker | Added `weft workspace dev` and a browser design selector. The bridge loads the registry, lists projects/designs, validates `/api/open` against discovered paths, rebuilds sessions, and broadcasts a fresh init to every client. | The registry needed a consumer; one local hub can now switch between registered project designs without restarting, while still rejecting arbitrary paths. | — |
| 2026-10-25 | Workspace registry | Added `@weft/workspace` and `weft workspace init/add/list/remove`: an explicit project-root allowlist, canonical real paths, unique display names, atomic owner-only storage, design discovery up to six levels with heavy/hidden/symlink directories skipped, and missing-project reporting. The bridge still opens one design per process; the project picker comes next. | Seeing other local projects must be an explicit, revocable grant rather than a home-directory scan. The registry is the narrow foundation for the project picker, dev-server supervision and capture allowlists. | [Local workspace design](../docs/local-workspace.md) |
| 2026-10-25 | Bridge security boundary |Made the bridge loopback-only, added a random per-run `HttpOnly` session cookie, Host/Origin checks, constant-time token comparison, a 1 MiB WebSocket payload limit and restrictive security headers. The app page sets the cookie; API and live WebSocket require it. Restarting the bridge rotates the token and requires open tabs to reload. | The bridge can write files and will soon see other projects; binding to localhost alone is not a trust boundary. This blocks cross-site browser requests and DNS rebinding without pretending to be team authentication. | ADR 0011 |
| 2026-10-25 | Repository security baseline | Added CI, CodeQL, dependency review, Dependabot, CODEOWNERS, the PR template, `SECURITY.md`, a threat model and a local-workspace design. Added scripts to configure branch protection and repository security settings; protected `main` with required `verify`, linear history, conversation resolution and no force pushes/deletions. | Weft will touch other local projects, run dev servers and accept agent commands; the repository and the local bridge need explicit boundaries before those features land. | — |
| 2026-10-25 | Browser editing and undo | Added DOM selection, a property inspector, browser commands over `/api/live`, atomic page writes from the bridge, attribution, and inverse-based undo/redo. The bridge now writes the changed page file and rolls the session back if the write fails; invalid commands return structured errors. | The bridge proved the file-to-browser loop; this slice proves command → page write → Yjs update → undo, using the same command vocabulary as agents and the CLI. | ADR 0010 |
